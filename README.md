# Magic Castle — 하늘의 수호자

GitHub Pages에서 실행하는 30스테이지 2D 판타지 게임입니다. `index.html` → `cloud.js`, `script.js`가 실제 실행 경로입니다. `boot.js`와 `game.js`는 현재 실행되지 않는 예전 3D 시안입니다.

- 기사: 높은 체력, 근접 자동 공격, 자동 보호막
- 법사: 원거리 자동 마법 공격, 얼음 지팡이로 시작
- 기존 검사 기록은 기사, 마법사·치유사 기록은 법사로 이전하며 성장 기록을 보존합니다.
- 비밀의 문에 닿으면 보물방으로 이동합니다. 상자 보상은 스테이지당 한 번이며 오른쪽 포털로 돌아옵니다.
- 체크포인트에서는 회복·공격·점프 축복 중 하나를 선택합니다.
- 3연속 처치마다 콤보 동전 보상을 받습니다.

## 저장

기기 저장은 플레이 중 5초마다, 일시정지 시 자동으로 수행됩니다. 클라우드 업로드는 사용자가 버튼을 눌렀을 때만 수행됩니다. 현재 스테이지의 획득 아이템, 적, 보물방, 축복, 체력과 장비 상태를 보관하고 마지막 위치에서 재개합니다. 불러오기 직후 1.5초 무적을 제공합니다. 비행 중 투사체와 시각 효과는 재개 시 초기화됩니다. 클라우드 덮어쓰기 확인과 버전 충돌 검사를 수행합니다.

## Supabase 설정

1. `supabase/setup.sql`을 프로젝트 SQL Editor에서 실행합니다. 이 채팅 작업 중 사용자 프로젝트에 이미 적용했습니다.
2. Authentication → URL Configuration의 Site URL과 Redirect URLs에 실제 게임 주소 `https://guras1984.github.io/MagicCastleEscape/`를 설정합니다. 로컬 테스트에는 `http://127.0.0.1:8765/`를 추가합니다.
3. Google Cloud에서 웹 OAuth 앱을 생성하고 승인된 리디렉션 URI로 `https://lubrwnbluclmpoxnkzul.supabase.co/auth/v1/callback`을 지정합니다. 동의 화면을 설정하고 공개 서비스 전 테스트 모드 제한을 확인합니다.
4. Supabase Authentication → Sign In / Providers → Google에 Client ID와 Client Secret을 입력하고 활성화합니다. Secret은 Supabase 설정 화면에만 입력합니다.
5. 게임의 클라우드 메뉴에서 구글 로그인 → 저장 → 다른 기기에서 불러오기를 확인합니다.

공개 프로젝트 URL과 Publishable key만 `cloud.js`에 있습니다. SDK는 클라우드 기능을 처음 사용할 때 로드합니다. 네트워크 문제에도 로컬 게임은 계속 작동합니다. RLS로 개인 저장 조회를 본인에게 제한하며 쓰기는 검증용 데이터베이스 함수를 거칩니다. 랭킹에는 이메일·계정 ID를 노출하지 않습니다.

## 온라인 랭킹

난이도와 직업별 상위 50명입니다. 완료한 단계 수, 획득 별, 합산 시간 순입니다. 각 스테이지는 최고 별·최단 시간 한 번만 집계합니다. 로그인한 상태로 스테이지를 시작하고 별명을 저장하면 클리어 시 자동 등록합니다. 별명 미설정 또는 통신 오류 시 최근 한 건을 기기에 보관하고 랭킹 화면에서 다시 등록할 수 있습니다. 중간 저장을 불러온 스테이지는 랭킹에서 제외하고 다음 스테이지부터 측정합니다. 실패한 도전은 완료 단계로 등록하지 않습니다.

서버는 소유권, 서버 측 시작 시각, 시간·피해량 범위, 중복 제출, 분당 시작 횟수를 확인하며 별과 순위는 서버에서 계산합니다. 브라우저 게임의 클리어와 피해량 자체를 서버에서 재현하지 않으므로 변조를 완전히 막는 경쟁용 검증은 아닙니다. 경품·경쟁 대회에 사용하려면 서버 게임 판정 또는 리플레이 검증을 추가해야 합니다.

## 검증

`node tests/game.cjs`로 기존 직업 변환, 저장/복원, 잘못된 저장 거부, 콤보·보물 중복 보상 방지, 랭킹 티켓 중복 방지, 30개 스테이지 업데이트·렌더링·저장을 확인합니다. 실제 구글 로그인 후 두 계정의 저장 분리와 다른 기기에서 복원하는 검증은 Google OAuth 설정 완료 후 수행해야 합니다.

게임 배포는 기존 GitHub Pages 저장소 루트 구성을 사용합니다. 별도 빌드가 필요하지 않습니다.
